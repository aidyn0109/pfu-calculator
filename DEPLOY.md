# Деплой на Render (free tier)

Пошаговая инструкция для развёртывания калькулятора ПФУ на [Render](https://render.com).

## Что используется
- **Web Service** (Python) — само приложение, запуск `uvicorn`.
- **PostgreSQL** (free) — основная БД вместо локального SQLite.
- Конфигурация описана в [render.yaml](render.yaml) (Blueprint).

---

## Шаг 1. Подготовка репозитория
1. Залейте проект в репозиторий GitHub/GitLab.
2. Убедитесь, что в репозиторий **не попали**: `pfu.db`, `.env`, `venv/`,
   `exports/`, `data/import/*.xlsx` (исключены в [.gitignore](.gitignore)).

> 💡 **Данные не хранятся в репозитории.** Excel с компаниями загружается уже
> после деплоя — через страницу администрирования прямо в браузере (см. шаг 5).

## Шаг 2. Создание сервиса через Blueprint
1. Render Dashboard → **New** → **Blueprint**.
2. Подключите репозиторий с этим проектом.
3. Render прочитает `render.yaml` и предложит создать:
   - базу данных `pfu-db` (PostgreSQL, free);
   - веб-сервис `pfu-calculator` (Python, free).
4. Нажмите **Apply**.

## Шаг 3. Переменные окружения
`DATABASE_URL` и `SECRET_KEY` подставятся автоматически. Вручную задайте в
настройках веб-сервиса (вкладка **Environment**):

| Переменная | Значение |
|---|---|
| `ADMIN_USERNAME` | логин администратора |
| `ADMIN_PASSWORD` | пароль администратора (надёжный) |
| `USER_USERNAME`  | логин обычного пользователя |
| `USER_PASSWORD`  | пароль пользователя |

После сохранения сервис автоматически перезапустится.

> `DATABASE_URL` от Render приходит в виде `postgresql://…`; приложение само
> приводит его к `postgresql+asyncpg://…` (см. `app/config.py`). Драйвер
> `asyncpg` уже в `requirements.txt`.

## Шаг 4. Первый запуск
- При старте приложение создаёт таблицы (`init_db`) в PostgreSQL.
- База будет пустой — это нормально, данные загрузим на шаге 5.
- Откройте URL сервиса → страница входа `/login` → войдите под админом.

## Шаг 5. Данные компаний
- **Первая загрузка — через браузер.** Войдите как админ → **Администрирование**
  → блок **Импорт из Excel** → выберите файл `.xlsx` → **Загрузить и импортировать**.
  Данные попадут в PostgreSQL и сохранятся между деплоями.
- **Добавление новых компаний** — там же, форма **Добавить компанию вручную**
  (БИН 12 цифр, наименование, показатели по годам).
- **Массовое обновление позже** — загрузите обновлённый `.xlsx` тем же блоком
  импорта (upsert по БИН: обновит существующие и добавит новые, ничего не удаляя).

Ожидаемые колонки файла: `БИН ТОО`, `Наименование ТОО`,
`Доходы 2022/2023/2024`, `Уплаченные налоги 2022/2023/2024`, `ФОТ 2022/2023/2024`.

## Шаг 6. Проверка
- `/login` — вход (health check Render тоже смотрит сюда).
- `/` — калькулятор (доступен обеим ролям).
- `/admin` — только для роли `admin`.

---

## Заметки про free tier
- Бесплатный веб-сервис «засыпает» при простое — первый запрос после паузы
  идёт с задержкой (cold start). Это нормально.
- Бесплатная база PostgreSQL на Render имеет ограниченный срок жизни — следите
  за уведомлениями в дашборде и делайте бэкап при необходимости.
- Локальная разработка по-прежнему работает на SQLite без изменений
  (`DATABASE_URL` не задан → fallback на `sqlite+aiosqlite:///./pfu.db`).

## Локальный запуск (напоминание)
```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env        # задать SECRET_KEY и учётки
uvicorn app.main:app --reload --port 8000
```
